# corp-messenger

Web-приложение корпоративного мессенджера с поддержкой тематических каналов и ролевого разграничения доступа. Монорепозиторий на npm workspaces: `server` — API на Node.js, `client` — интерфейс на React.

## Возможности

- Регистрация сотрудников с корпоративной почтой `@corp.messenger.com` и вход по паре JWT-токенов.
- Тематические каналы: публичные и приватные, каталог с вступлением, управление участниками и локальными ролями.
- Обмен сообщениями в реальном времени через WebSocket: лента, отправка, удаление по правам.
- Панель администратора: реестр сотрудников, блокировка аккаунтов, назначение глобальных ролей.

## Запуск

Предусловия: Node.js 22, PostgreSQL 17.

1. Установить зависимости: `npm ci`.
2. Скопировать `server/.env.example` в `server/.env` и заполнить `DATABASE_URL` и `JWT_SECRET`.
3. Применить миграции: `npm run prisma:deploy -w server`.
4. Собрать сервер: `npm run build -w server`.
5. Запустить сервер: `npm run start -w server` → API на `http://localhost:3000`. Запуск занимает терминал, остановить — `Ctrl+C`.
6. Запустить клиент в отдельном терминале: `npm run dev -w client` → интерфейс на `http://localhost:5173`.

Интерфейс опубликован на GitHub Pages: <https://igordel004.github.io/corp-messenger/>. Серверная часть запускается локально — см. раздел «Запуск». Адрес API для продакшен-сборки клиента задаётся переменной `VITE_API_URL` в `client/.env.production`.

## Тесты

| Команда                 | Что делает                                        |
| ----------------------- | ------------------------------------------------- |
| `npm test`              | полный прогон набора тестов                       |
| `npm run test:coverage` | прогон с отчётом о покрытии кода                  |
| `npm run test:report`   | прогон с JUnit- и JSON-отчётами, сводка в консоль |

Тесты выполняются в отдельной базе `corp_messenger_test`: создайте её и примените миграции, указав её адрес в `DATABASE_URL`. Перед прогоном и после него все таблицы обнуляются командой `TRUNCATE`. Хук `pre-commit` генерирует отчёт при каждом коммите.

## CI/CD

Конвейер GitHub Actions выполняет при каждом push и Pull Request статический анализ, тесты с контейнером PostgreSQL 17, сборку сервера и клиента и сбор метрик качества. Слияние в ветку `main` разворачивает клиент на GitHub Pages.
